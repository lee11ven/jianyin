# 左右手骨架提取 · 最小可落地单元

> 落地切片计划。算法全文见 [../左右手骨架提取.md](../左右手骨架提取.md)。本单元只交付「track_id + hand_state/handedness 槽位；冲突拒发」。

**执行序号：⑤**（最后）。依赖 ④ [帧手势骨架提取](./帧手势骨架提取.md) 已出 Hands 21 点。总序见 [index.md](./index.md)。

## 技术栈

| 项 | 选型 |
|----|------|
| 实现位置 | 同 `lib/skeleton/`，无独立包 |
| 跟踪 | Dart：腕近邻 `track_id` + 标签锁 |
| 手性信号 | MediaPipe 自带 `handedness` + 抽帧 `hand_state` |
| 输出 | 定长 42 槽位写入（复用 ④ 打包） |

## 第三方库

| 库 | 用途 | 说明 |
|----|------|------|
| （无新增） | 槽位融合 / 冲突拒发 | 自研；消费 ④ Hands 结果 |
| Hand Landmarker handedness | 单帧概率 | 已由 ④ 引入，本单元只读 |

## 目标 / 非目标

| 项 | 说明 |
|----|------|
| 目标 | 腕近邻维护 `track_id`；标签融合：稳定 track > `hand_state` > 单帧 `handedness`；定长槽正确；连续冲突该槽 `v=0` |
| 非目标 | 拇指朝向先验 `T_thumb`、交叉态冻结改标、互遮完整策略、腕 `x` 序（N0 双手辅助可二期再开） |

## 输入 / 输出契约

| 方向 | 内容 |
|------|------|
| 输入 | Hands 检出（最多 2 手）+ 抽帧 `hand_state` / `roi` / `viewpoint_class` |
| 输出 | 定长 42：`[0:21)=left`，`[21:42)=right`；信封侧 `present` 可后补 |
| 拒发 | 标签冲突连续 `N_conflict` → 该手或整帧手形拒发；**禁止**镜像编造另一手 |
| 不上行 | `track_id`、`label`、内部冲突计数 |

省略某手 ≠ `path.gap`。

## 落地步骤

1. 每检出腕 + 掌心（或腕）速度做最近邻，关联已有 `track_id`；超距新建轨。
2. 单手 `hand_state=left|right`：只填对应槽；另一槽全 `v=0`；短时 handedness 翻转时继承上一稳定标签。
3. 双手 `both`：两轨分别得候选标签；同帧禁止双 left / 双 right——保留稳定 track 对，否则整帧拒发优于错槽。
4. 融合优先级（MVP）：① 已锁 `N_lock` 帧的 track 标签 ② `hand_state` ③ MediaPipe `handedness_prob ≥ P_hand`。
5. 有效比仍走帧手势门控；冲突累计 → 槽位 `v=0`，可选 `low_quality` 回馈抽帧。
6. 交叉/遮挡：MVP 不实现；若 IoU 异常导致标签乱跳，走冲突拒发即可。

## 验收口径

| 指标 | 通过线 |
|------|--------|
| 单手槽位正确率 | `hand_state∈{left,right}` 时上行槽与标注一致 |
| 无镜像编造 | 冲突/缺手时不对侧槽写入镜像点 |
| 错槽拒发 | 双手标签张力时整帧或冲突手拒发，不上行对调点集 |
| 与轨迹解耦 | 手形拒发不强制 `path.gap` |
