# 运动轨迹 · 最小可落地单元

> 落地切片计划。算法全文见 [../运动轨迹.md](../运动轨迹.md)。本单元只交付「活动段腕路径 + 显式 gap + body/image 空间切换」。

**执行序号：③**。依赖 ① 时钟、② `BodyAxes`。总序见 [index.md](./index.md)。

## 技术栈

| 项 | 选型 |
|----|------|
| 节拍 | 抽帧 `Active` 固定 `Δt_path`（Dart） |
| 腕来源（MVP） | 先用 ② Pose `wristL/R`；④ 就绪后改为 Hands track 腕注入 |
| 坐标 | 有 `BodyAxes` → 肩宽归一 `space=body`；否则 `image` |
| 依赖库 | **无新 ML 库**；纯 Dart 跟踪与 gap |

## 第三方库

| 库 | 用途 | 说明 |
|----|------|------|
| （无新增） | path 采样 / gap / 空间切换 | 自研 `TrajectoryTracker` |
| Pose / Hands（经 ②④） | 腕点输入 | 本单元只消费，不直接绑 SDK |
| 光流 / OpenCV | 腕丢兜底 | **延后** |

## 目标 / 非目标

| 项 | 说明 |
|----|------|
| 目标 | 固定 `Δt_path` 节拍写左右 `wrist`；腕丢或 `forceGap` → `gap:true`；有 axes → `space=body`，否则 `image` |
| 非目标 | 五指尖主 `trace`、光流兜底、云端 shape/direction/repeats、部位序列挂接 |

## 输入 / 输出契约

| 方向 | 内容 |
|------|------|
| 输入 | `ts`；`BodyAxes?`；`forceGap`（抽帧重抖/红档占位）；腕位置来源（Hands 跟踪或 Pose 腕，MVP 二选一，优先 Hands 腕若已跑） |
| 输出 | `PathChannel`：`space` / `anchor` / `gap`；非 gap 时填 `left`/`right.wrist`（掌心可用腕降权占位） |
| 不上行 | 形状结论、`places`、`contactSite` |

与 [`path_types.dart`](../../../../jianyin_app/lib/trajectory/path_types.dart)、[`csl_channels.dart`](../../../../jianyin_app/lib/envelope/csl_channels.dart) 字段一致。

## 落地步骤

1. 替换 [`StubTrajectoryTracker`](../../../../jianyin_app/lib/trajectory/trajectory_tracker.dart)：仅在抽帧 `Active` 节拍被调用（由 camera 调度保证）。
2. 每拍：若 `forceGap` 或腕跟踪失效 → 返回 `gap: true`（可只留 `space`/`anchor`/`gap`）。
3. 腕有效：写入对应手 `wrist`（图像坐标）；若有 `axes`，换算为肩宽归一身体坐标后设 `space=body`、`anchor=true`。
4. 掌心 MVP：无 MCP 均值时，`palm = wrist` 且 `v` 降权（对齐设计「掌心不足则记为腕」）。
5. 五指尖：MVP 各位 `v=0` 占位，不扩 `path` 到 21 关节。
6. 缺手槽保留，各位 `v=0`；不做 One-Euro（设计锁定）。

## 验收口径

| 指标 | 通过线 |
|------|--------|
| 节拍连续 | 活动段内非 gap 拍 path 与 `ts` 对齐、间隔近似 `Δt_path` |
| 显式断点 | 腕丢或 `forceGap` 时 `gap: true`，不编造位移 |
| 空间切换 | 有 `BodyAxes` → `space=body`；无 → `space=image` 且 `anchor=false` |
| 与手形解耦 | 省略 `hands` 时仍可有非 gap 的腕 path |
