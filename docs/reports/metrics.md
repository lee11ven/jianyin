# 性能指标实测表

本文件是**性能与可扩展性**维度的实测证据来源：所有数值均由仓库内脚本产生，可一条命令复现。
凡标注「离线 harness」的项为合成序列（非真机采集），其判定门限与真机复测口径一致；
真机复测步骤见 [device-acceptance.md](./device-acceptance.md)。

## 1. 端侧（客户端）指标

- 采集方式：**离线 harness**（合成音频到货序列 / 合成抽帧序列）
- 复现命令：`cd jianyin_app && flutter test test/metrics_harness_test.dart`
- 环境：Windows 10 / Flutter 3.35.7（Dart VM，无真机与音频回路）

| 指标 | 实测值 | 门限 | 口径与说明 |
|------|--------|------|------------|
| 端侧开声缓冲时延 | **30 ms** | ≤ `T_prime`（100 ms） | 模型：首片 30 ms 到货、第二片 60 ms 到货、其后 100 ms 节奏；缓冲跨过 100 ms 即开声 |
| 欠载率 | **0.0%** | ≤ 2% | 抖动场景：每 5 片插入一次 60 ms 到货抖动，活动播报区间内 `Underrun` 时长为 0 |
| 弱网停顿恢复 | **250 ms** | ≤ 400 ms（停顿时长） | 停发 400 ms 后重新到货，恢复播放耗时 250 ms；停顿时抛 `hint.network_audio` |
| 抖动触发欠载次数 | **0** | ≤ 3 次 / 2 s | 未达 `N_underrun_hint=3`，故不亮弱网提示 |
| 抽帧漏帧率（动作峰值帧） | **0.0%**（0/12） | ≤ 3% | 25 Hz 合成帧，每 250 ms 一段持续运动、段中一帧为峰值；全部放行（`PeakHold` 生效） |
| 重抖拒发（安全性） | **是** | 必须拒发 | 能量 = 5×`tOnset` → `Reject`（不送手形 + 轨迹 `gap`） |
| 轻抖放行 | **是**（`light`） | 保留采样 | 能量 = 2×`tOnset` → 分档 `light`，仍放行 |

## 2. 服务端（网关）指标

- 采集方式：**真实起网关 + 50 并发会话压测**
- 复现命令：
  ```bash
  cd websocket-server
  node src/index.js &            # 默认 0.0.0.0:8000
  node scripts/load-test.mjs --url http://127.0.0.1:8000 --sessions 50 --seconds 6
  ```
- 环境：本机回环（127.0.0.1）、Node v22.22.3、单进程

| 指标 | 实测值 | 门限 | 说明 |
|------|--------|------|------|
| 并发会话 | **50**（全部建立并出声） | ≥ 50 | `sessionsWithAudio = 50/50` |
| 上行速率 | **924.9 msg/s** | 15–30 Hz/会话 | 50 会话 × 25 Hz ≈ 1250 msg/s 目标，实测含建连阶段 |
| 消息延迟 P50 | **17 ms** | — | 「上行 `sentAt` → 收到 `recognition`/`audio.header`」 |
| 消息延迟 P95 | **40 ms** | ≤ 100 ms | 同上 |
| 消息延迟 Max | **52 ms** | — | 同上 |
| TTS 首片延迟 P50 | **23 ms** | ≤ 300 ms | 识别产出 → 首个 `audio.header` |
| TTS 首片延迟 P95 | **40 ms** | ≤ 300 ms | 同上 |
| 端到端开声延迟 | **断言 < 1500 ms 通过** | ≤ 1.5 s | 端到端测试 `websocket-server/test/e2e.test.js` 实测断言 |
| 音频输出 | 600 片 / 1,664,000 字节 | PCM s16le 16 kHz mono | 100 会话句（50 会话 × 2 句） |

## 3. 待真机复测的项（口径已定，尚未取数）

| 指标 | 门限 | 复测方式 |
|------|------|----------|
| 漏帧率（真机采集） | ≤ 3% | 按真机步骤录制活动段，统计应保留却未抽中的关键动作帧 |
| 模糊拒帧率 | ≤ 15% | 活动区间内因清晰度/拖影门控被拒的帧占比 |
| 分机位可抽帧率 | N0 ≥ 80%；A1–A8 ≥ 60% | 分别摆出 N0 与 A1–A8 机位，统计放行率（`viewpoint_class` 已随上行日志输出） |
| 单双手/槽位/拇指一致率 | ≥ 95% | 标注集比对（见 `docs/design/客户端APP/roadmap.md`） |
| 端侧开声缓冲时延（真机） | ≤ `T_prime` | 真机打点：首片到达 → `Playing` 状态 |

> 说明：上一版「实现期采数」占位已全部替换为上述**量化门限**；真机项保留待测状态，避免把未验证当已通过。
